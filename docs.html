LAAFFIC 短剧 · 对接文档

LAAFFIC 短剧：把合规的海外短剧内容接进你的 App——内容 API + 客户端 SDK。 一句话：我们只提供内容与播放；你的 App 里的奖励、任务、商店、广告、支付，都由你自己实现。 文档版本 2026-11 · SDK @laffic/content-sdk@1.0.0 / Android ai.laffic.sdk:content:1.0.0 / LAAFFICContentSDK XCFramework · 2026-11

#0. 30 秒读懂

问题 答案
你能得到什么 5,000+ 部正版短剧（30 万+ 集、10+ 语种，套餐可开通 100–500 部）的内容接口与播放能力：语种、分类、标签、列表、搜索、详情、播放地址、播放埋点
你要准备什么 4 个值：appId、appSecret、uid、pkgName；一个后端（或直接用我们的签名示例）
接入周期 3 天：D1 登记 + 服务端签名跑通 → D2 列表/详情/播放 → D3 埋点与联调验收
你会改什么 不改你的核心漏斗：不加 Tab、不抢首屏；内容放在你想放的位置
我们不做什么 不做奖励/任务/商店/广告/支付；这些由你的 App 自己实现
谁负责播放稳定性 我们负责内容、CDN、播放地址与 License；播放器由你选（SDK 模式可提供封装）

两种交付模式：SDK（客户端封装 + 播放器 License，3 天上线）或 API（服务端 Open API，客户自建 UI，1–2 天）——怎么选看 00 接入模式。

#1. 能力边界（先看这一页，避免误会）

能力 谁负责 说明
短剧内容（剧库、语种、分类、标签、封面、详情） LAAFFIC 按套餐提供；每季度《内容清单》
播放地址（HLS / 腾讯云 fileId）与防盗链 LAAFFIC 带 expireTime 的时效地址；SDK 模式含播放器 License
播放埋点（25/50/75/100、PLAY_END） LAAFFIC 纯内容统计，不与奖励挂钩
CDN 与播放稳定性 LAAFFIC 200+ 节点；播放器兼容性由 SDK 模式覆盖
UI / 导航 / 页面结构 客户 不加 Tab、不抢首屏由你决定放哪
播放器（非 SDK 模式） 客户 API 模式自选播放器
奖励 / 任务 / 商店 / 广告 / 支付 / 游戏玩法 客户 我们一概不提供、不托管、不结算

文档里出现的 appId/uid 只用于鉴权与内容分发；我们不做用户画像、不做广告投放、不经手任何资金。

两条硬约束：

  1. appSecret 只能出现在你的服务端（或受控的 BFF）。Web/Android/iOS 客户端不要硬编码密钥；SDK 的 appSecret 参数仅用于 Demo / 内网联调，生产环境请改用「服务端换 token + 下发短期 token」模式（见 02 §9）。
  2. 播放地址不外泄、不落日志、不导出；按 expireTime 刷新，过期即失效（见 09 §5）。

#6. 三个不能碰的承诺

  1. 3 天接入：一个前端 + 一个后端就能跑通；接口全部是 POST + JSON，没有 SDK 专属私有协议。
  2. 不改变你的核心漏斗：不加 Tab、不抢首屏、不打断游戏；内容放哪、什么时候放，由你决定。
  3. 只做内容：不做奖励/任务/商店/广告/支付；不参与你的资金与运营结算。

00 · 接入模式：SDK 还是 API

你会得到什么：一次把「选 SDK 还是选 API」定下来——两种模式各交付什么、怎么选（3 条决策）、能不能混用、按什么口径计费。 你需要准备什么：一个能拍板的人（技术负责人/产品），以及「有没有客户端团队」这个事实。

先说结论：内容、签名、接口、计费底座都是同一套。两种模式的差别只有一个——UI 和播放器由谁写：

SDK 模式 API 模式
谁写 UI / 播放器 我们（SDK 内置，可选组件） 你（自建 UI + 自选播放器）
你对接的东西 客户端 SDK（Android / iOS / H5） 服务端 HTTP Open API
接入周期 3 天（1 前端 + 1 后端） 1–2 天（后端）
本质 短剧内容服务 + 客户端封装 短剧内容服务 + 服务端 Open API

能力边界：两种模式提供的都是短剧内容与播放（列表/搜索/详情/播放地址/播放埋点）。奖励、任务、商店、广告、支付、游戏玩法由客户自行实现，不在交付范围内。

计费方式见 §6；具体价格只写在商务报价单 / 销售 Deck 里，本文不写价格。

UI 可选组件：剧场/详情/播放页；也可只用数据 全部由客户自绘（列表、详情、播放页…）

共同点（不管选哪个都一样）：

  • 同一份剧库与《内容清单》、同一套 CDN 与防盗链；
  • 同一套鉴权：appId + uid + apiSignature（AES-CBC）+ timestamp + nonce + token（见 02）；
  • 同一套内容接口：/sdk/app/*（语种/分类/标签/列表/搜索/详情/播放地址/播放埋点，见 03）；
  • 同一套鉴权、限流与防盗链；
  • 同一份《内容清单》与合规要求（09）。

#4. 怎么选：3 条决策

#决策 1：有没有客户端团队 / 要不要 3 天上线？

  • 只有后端、或客户端排期紧 → SDK 模式（客户端只需"拉起播放器 + 回调"，1 天能接完）。
  • 有成熟客户端团队、且已有播放器体系 → API 模式（只写后端，1–2 天）。

#决策 2：要不要完全自控 UI 与播放器？

  • 品牌一致性要求高、已有播放器、要接 DRM/AirPlay/画中画、多端一致 → API 模式（或 SDK 内容 + 自建播放器，见 §5）。
  • 只要"能播、能取数"、不想碰播放器细节 → SDK 模式。

#决策 3：载体是什么？

载体 推荐 原因
原生 App（游戏/工具/内容） SDK 有 AAR/XCFramework，播放器与 License 都给了
H5 / 微信小程序（WebView） SDK（H5） 或 API H5 SDK 单文件可跑；小程序若限制 <video> 能力则用 API 自绘
纯后端分发（白标 / 二次开发） API 你对外提供 UI 与品牌，我们只做内容与接口
游戏（俄罗斯方块/消除/跑酷…） SDK 播放器用 SDK 覆盖层最省事；内容放哪由游戏自己定
智能电视 / 车机 / 特殊终端 API 播放器通常需定制，SDK 无对应端

#5. 两种模式能不能混用？

能，而且常见。 四种组合：

组合 做法 适用 注意
A. SDK 内容 + 自建播放器 用 SDK 拿列表/详情/播放地址，自己的播放器播 已有播放器、要复用 SDK 的鉴权与发奖 仍用 refreshPlayUrl 刷地址；进度仍要上报
B. API + 自建 UI 标准 API 模式 白标 / 内容 App / 特殊终端 签名、token、两段式发奖都要自己做
C. SDK + 服务端 API 同时用 客户端用 SDK；服务端也用 API（对账、补发、后台配置） 需要服务端对账/运营工具 同一 appId、同一 uid 体系；服务端自己换 token，别复用客户端 token
D. SDK 模式 + 我们提供的 UI 组件 直接用剧场/播放页组件 3 天上线、无设计资源 可换肤；不改导航结构

不建议的混法（会踩坑）：

混法 后果
两套 appId / 两套内容源 收藏/已看不互通，数据对不上
客户端持 appSecret 自己签名（生产） 密钥可被逆向，任何人可冒用你的 appId（02 §9）
绕过防盗链导出永久播放地址 违反版权授权，可能被停服（09 §2）

混用时统一一个 appId + 一套 uid，收藏/已看/播放进度都以同一 uid 为准。

#1. 接入前置清单（缺一项就会在 init 卡住）

# 事项 谁做 怎么算完成 失败现象
1 开放平台创建 App，拿到 appId / appSecret 你 + 我们商务 后台能看到 App 状态「已激活」 dataCode=1001 签名错误

02 · 鉴权与签名（AES-CBC）

你会得到什么：一套四语言可复制运行的签名实现、固定输入对应的期望输出、以及 9 类签名错误的排错表。 你需要准备什么：appId、appSecret（恰好 16 字节 UTF-8）、uid、pkgName；服务端时钟已同步 NTP。

签名是本 SDK 唯一"必须自己实现"的东西。接口全部是 POST + JSON，没有私有协议；只要签名对，后面的接口都是普通 HTTP。

#1. 鉴权模型：谁签名、token 怎么来

text
① 你的服务端 / SDK
   POST /sdk/app/getAccessToken        ← 只需 appId + apiSignature（不带头 token）
   └── 返回 token + expiresIn（绝对秒级时间戳）+ 播放器 Licence

② 后续所有接口
   POST /sdk/app/...（内容接口）
   └── 请求头带 token（+ 每次重新签名）

③ token 失效
   响应 data.dataCode = 1002  →  重新执行 ①（同一 uid）→ 重试原请求一次
角色 是否持有 appSecret 说明
你的服务端 / BFF ✅ 持有 签名在这里做，token 也从这里换（推荐生产形态）
Web / Android / iOS 客户端 ⚠️ 仅 Demo/内网联调 SDK 暴露 appSecret 参数是为了让 Demo 与离线 mock 能自签；生产环境请改为下发短期 token，见 §9
LAAFFIC 网关 ✅ 校验方 校验签名、时间戳、nonce、token、uid 归属

uid 由你生成并持久化：同一用户在多端、多次会话都必须是同一个值。收藏、点赞、已看都挂在 uid 上。换 uid 等于换账号。

#2. 公共请求头

请求头 类型 必填 说明
Content-Type string ✅ 固定 application/json; charset=utf-8
appId string ✅ 平台分配的应用标识
uid string ✅ 你的用户唯一标识（稳定不变）
apiSignature string ✅ 签名结果，AES-CBC 加密后的 Base64 标准字符串
timestamp string ✅ 请求时间戳，毫秒；与签名串第 3 行完全一致
nonce string ✅ 32 位随机串；与签名串第 4 行完全一致
token string ⬜ 授权令牌；除 getAccessToken 外必填
version string ⬜ SDK 版本号，便于我们排查（可选，如 1.0.0）

getAccessToken 是唯一不需要 token 头的接口（它就是用签发 token 的）。

#3. 签名串：5 行，每行都以 \n 结尾

原文（第 5 行是请求体原始 JSON 字符串）：

text
HTTP方法\n
URI（不含域名）\n
时间戳（毫秒，与请求头一致）\n
nonce（32 位，与请求头一致）\n
请求体原始 JSON\n
行 内容 正确示例 常见错误
1 方法，必须大写 POST 传 post
2 URI，不含域名，含网关前缀与应用前缀 /sdk/app/getAccessToken 传完整 URL https://open.laaffic.io/sdk/sdk/app/getAccessToken
3 时间戳，毫秒字符串 1750242209899 用秒级 1750242209
4 nonce，32 位 a1b2c3d4e5f60718293a4b5c6d7e8f90 用 16 位、或用 - 分隔的 UUID（36 位）
5 发送时那份 body 原样字符串 见下 先签名再 JSON.stringify（空格/顺序变了）；或签名用对象、发送用压缩后的串

固定示例（下文所有语言都用它，可直接核对）：

text
POST\n/sdk/app/getAccessToken\n1750242209899\na1b2c3d4e5f60718293a4b5c6d7e8f90\n{"baseInfo":{"model":"SM-G9810","brand":"samsung","manufacturer":"samsung","device":"x1q","osVersion":"12","language":"zh","pkgName":"ai.laffic.demo"},"data":{"paramMd5":"fa963870aa46ccd6fae9d61941d515c1"}}\n

第 5 行的唯一铁律：计算签名时用的字符串，必须与 fetch / HttpClient / OkHttp 真正发出去的 body 逐字节相同。最稳的做法是：先 bodyStr = JSON.stringify(obj)，然后用 bodyStr 同时算签名和发请求。

#4. AES-CBC 参数

参数 值
算法 AES
模式 CBC
填充 PKCS5Padding（Java 叫法）/ PKCS7（OpenSSL、Node、Go、Python 叫法）——在 AES 的 16 字节块下两者等价
密钥 Key appSecret 的 UTF-8 字节，必须 16 字节 → AES-128
初始向量 IV 与 Key 相同，即 appSecret 的 UTF-8 字节
输出编码 Base64 标准表（含 + /，尾部 = 补齐），不是 URL-safe
待加密内容 签名串的 UTF-8 字节（含末尾 \n）

#四个必错点

  1. appSecret 长度 ≠ 16 字节：中文/emoji 会让"16 个字符"变成 >16 字节。用 printf '%s' "$SECRET" | wc -c 核对。
  2. Base64 用了 URL-safe：把 +// 换成 -/_ 会验签失败。
  3. IV 用了全 0：参照实现里 IV = Key，不是全零向量。
  4. 签名串少了最后的 \n：5 行都要 \n，包括最后一行。

// laffic-sign.mjs —— 完整脚本见 docs/tools/sign_example_node.mjs
import crypto from 'node:crypto';

const APP_SECRET = 'LAAFFIC_DEMO_168'; // 恰好 16 字节 UTF-8

// paramMd5 = MD5(uid + appId + appSecret + pkgName) 的 32 位小写（仅 getAccessToken 用）
export function paramMd5(uid, appId, appSecret, pkgName) {
  return crypto.createHash('md5').update(uid + appId + appSecret + pkgName, 'utf8').digest('hex');
}

// 签名串 5 行，每行以 \n 结尾（含最后一行）
export function buildSignString(method, uri, timestamp, nonce, body) {
  return `${method}\n${uri}\n${timestamp}\n${nonce}\n${body}\n`;
}

// AES-128-CBC / PKCS7 / Key=IV=appSecret / Base64
export function apiSignature(appSecret, method, uri, timestamp, nonce, body) {
  const key = Buffer.from(appSecret, 'utf8');
  if (key.length !== 16) throw new Error(`appSecret 必须是 16 字节 UTF-8，当前 ${key.length} 字节`);
  const cipher = crypto.createCipheriv('aes-128-cbc', key, key);
  const out = cipher.update(buildSignString(method, uri, timestamp, nonce, body), 'utf8', 'base64');
  return out + cipher.final('base64');
}

// 32 位随机串（16 字节 hex）；生产用 crypto.randomBytes，别用 Math.random
export function nonce() {
  return crypto.randomBytes(16).toString('hex');
}

def param_md5(uid: str, app_id: str, app_secret: str, pkg_name: str) -> str:

    return hashlib.md5((uid + app_id + app_secret + pkg_name).encode("utf-8")).hexdigest()


def build_sign_string(method: str, uri: str, timestamp: str, nonce: str, body: str) -> bytes:
    """签名串 5 行，每行以 \\n 结尾（含最后一行）"""
    return f"{method}\n{uri}\n{timestamp}\n{nonce}\n{body}\n".encode("utf-8")


def api_signature(app_secret: str, method: str, uri: str, timestamp: str, nonce: str, body: str) -> str:
    """AES-128-CBC / PKCS7 / Key=IV=appSecret / Base64"""
    key = app_secret.encode("utf-8")
    if len(key) != 16:
        raise ValueError(f"appSecret 必须是 16 字节 UTF-8，当前 {len(key)} 字节")

    padder = padding.PKCS7(128).padder()  # 128 bit = 16 字节块
    padded = padder.update(build_sign_string(method, uri, timestamp, nonce, body)) + padder.finalize()

    encryptor = Cipher(algorithms.AES(key), modes.CBC(key)).encryptor()
    return base64.b64encode(encryptor.update(padded) + encryptor.finalize()).decode("ascii")


def nonce() -> str:
    """32 位随机串（16 字节 hex），用 secrets 不要用 random"""
    return secrets.token_hex(16)

// laffic_sign.go
package laffic

import (
    "bytes"
    "crypto/aes"
    "crypto/cipher"
    "crypto/md5"
    "crypto/rand"
    "encoding/base64"
    "encoding/hex"
    "fmt"
    "strings"
)

// ParamMD5 = MD5(uid + appId + appSecret + pkgName) 的 32 位小写
func ParamMD5(uid, appID, appSecret, pkgName string) string {
    sum := md5.Sum([]byte(uid + appID + appSecret + pkgName))
    return hex.EncodeToString(sum[:])
}

// BuildSignString 签名串 5 行，每行以 \n 结尾（含最后一行）
func BuildSignString(method, uri, timestamp, nonce, body string) string {
    return strings.Join([]string{method, uri, timestamp, nonce, body}, "\n") + "\n"
}

// APISignature AES-128-CBC / PKCS7 / Key=IV=appSecret / Base64
func APISignature(appSecret, method, uri, timestamp, nonce, body string) (string, error) {
    key := []byte(appSecret)
    if len(key) != 16 {
        return "", fmt.Errorf("appSecret 必须是 16 字节 UTF-8，当前 %d 字节", len(key))
    }
    block, err := aes.NewCipher(key)
    if err != nil {
        return "", err
    }
    plain := []byte(BuildSignString(method, uri, timestamp, nonce, body))

    // PKCS7 填充
    pad := block.BlockSize() - len(plain)%block.BlockSize()
    padded := append(plain, bytes.Repeat([]byte{byte(pad)}, pad)...)

    out := make([]byte, len(padded))
    cipher.NewCBCEncrypter(block, key).CryptBlocks(out, padded) // IV = appSecret
    return base64.StdEncoding.EncodeToString(out), nil
}

// Nonce 32 位随机串（16 字节 hex）
func Nonce() string {
    b := make([]byte, 16)
    _, _ = rand.Read(b)
    return hex.EncodeToString(b)
}

    """AES-128-CBC / PKCS7 / Key=IV=appSecret / Base64 —— 调 openssl enc，零 Python 依赖"""

#7. 防重放、时间戳与 token 生命周期

机制 规则 服务端处理 失败返回
时间戳窗口 abs(serverNow - timestamp) ≤ 5 分钟 超出直接拒绝 dataCode=1003（时间戳过期）
nonce 唯一 32 位随机串，每请求不重复 Redis SET key NX EX 300，key = nonce:{appId}:{nonce} 重复 → dataCode=1001（签名/验签失败族）
签名 5 行串 AES-CBC 后 Base64 用同一份 body 字节重算并常量时间比较 dataCode=1001
uid 归属 uid 必须属于该 appId 校验 uid 绑定关系 dataCode=1001
token 除 getAccessToken 外必填 校验签名与过期时间 过期/无效 → dataCode=1002
幂等键 领奖、转盘、兑换必须带 idempotencyKey 同 key 返回首次结果，不重复发奖 重复领取 → dataCode=2003

#token 细则

  • expiresIn 是绝对过期时间（秒级 Unix 时间戳），不是"剩余秒数"。示例 1786098419 → 2026-08-06 左右。
  • 服务端/客户端都应在过期前 5 分钟主动刷新；不要等 1002 再刷（会有一次失败）。
  • 同一 uid 重新换 token 时，旧 token 有 5 分钟重叠期（避免并发请求直接失败）。
  • 客户端内存缓存 token 即可，不要写日志、不要上报到分析平台。
js
// token 缓存 + 提前刷新（Node 示例）
let cache = { token: '', expireAt: 0 };
async function getToken() {
  if (cache.token && Date.now() < cache.expireAt - 5 * 60 * 1000) return cache.token;
  const init = await callAccessToken();          // 见 03 §3.1
  cache = { token: init.token, expireAt: init.expiresIn * 1000 };
  return cache.token;
}

1. 取 appId              → 不存在 → dataCode=1001
2. 校验请求头齐全        → 缺 appId/uid/timestamp/nonce/apiSignature → dataCode=1001
3. 时间戳窗口 ±5min      → 超窗 → dataCode=1003（先测时间戳，避免"时钟漂移"被误报成签名错）
4. nonce 未被使用        → 已用过 → dataCode=1001
5. 取 body 原始字节重算签名 → 不一致 → dataCode=1001
6. （除 getAccessToken）校验 token → 无效/过期 → dataCode=1002
7. 校验 uid 归属 appId    → 不属于 → dataCode=1001
8. 业务校验（内容是否存在/是否下架/地区）→ 3001
9. 成功 → dataCode=0

第 5 步必须用原始 body 字节，不要 JSON.parse 再序列化：字段顺序、空格、1.0 vs 1、中文转义都会变。

#9. 生产安全形态（推荐）

text
客户端 ──HTTPS──> 你的服务端（持 appSecret）
                    │ 1. 签名 + 换 token
                    │ 2. 把 token 下发客户端（短期，随会话）
                    ▼
             LAAFFIC 网关 https://open.laaffic.io/sdk
形态 谁签名 适用 风险
A. 客户端直连 + 内置 appSecret 客户端 仅 Demo / 内网联调 密钥可被逆向，任何人可冒用你的 appId
B. 客户端拿短期 token（推荐） 你的服务端 生产默认 需要你有后端；token 泄露窗口受限
C. 全部走服务端代理 服务端 强合规 / 无客户端改造 你的服务端承担全部流量，注意带宽与并发
  • 走 B/C 时，客户端每次请求仍要带 apiSignature：签名可以放在你的 BFF 完成，客户端只负责转发（SDK 支持 signer 回调，见 04 §3）。
  • WebCrypto 只用于 Demo：浏览器里没有真正的秘密。生产 Web 场景必须走 BFF。
  • 密钥轮换：平台支持双密钥灰度（新密钥生效后旧密钥保留 7 天），轮换期间两套并存，切换不中断。

#10. 签名错误排查表（dataCode=1001 全家族）

现象 根因 验证方法 修复
一直 1001，换语言仍错 appSecret 不是 16 字节 printf '%s' '你的 secret' \| wc -c 找我们核对密钥
Node 对、Java 不对 Java 用了 AES/CBC/NoPadding 或自定义填充 打印签名串前 40 字符 改 AES/CBC/PKCS5Padding
偶发 1001（约 1/10） body 被二次序列化（框架美化/重排字段） 记录签名用 body 与发送 body 的 md5 先序列化再签名，用同一字符串发送
1001 且 dataMsg 提示时间 服务器时钟漂移 > 5 分钟 date -u 对比 NTP 开 chrony/NTP，容器同步宿主时钟
1001 且日志有重放提示 nonce 复用（重试时没换 nonce） 打印每次 nonce 重试必须重新生成 nonce + 时间戳 + 签名
Base64 解码失败 用了 URL-safe Base64 或带了换行 echo -n "$sig" \| base64 -d 标准 Base64，单行输出，去掉换行
1002 token 过期 缓存未刷新 / 多实例各自换 token 看响应 expiresIn 过期前 5 分钟刷新，按 uid 维度集中缓存
1003 时间戳过期 用了秒级时间戳，或示例里的固定时间戳 请求头 timestamp 是否 13 位 用 Date.now() / System.currentTimeMillis()
URI 不匹配 第 2 行写成完整 URL，或漏了网关前缀 打印签名串第 2 行 只写 /sdk/app/...

#11. 签名自检清单（贴到你的 PR 模板里）

  • [ ] 签名串 = METHOD\nURI\nTS\nNONCE\nBODY\n，5 行都以 \n 结尾
  • [ ] appSecret 的 UTF-8 字节数 = 16
  • [ ] AES-128-CBC + PKCS5/PKCS7 + IV = Key = appSecret
  • [ ] Base64 标准表、单行、无空格
  • [ ] timestamp 毫秒、与请求头一致；nonce 32 位、与请求头一致
  • [ ] 签名与发送使用同一个 body 字符串
  • [ ] 用本文 §6 的固定输入跑出完全相同的 3 个 apiSignature
  • [ ] 服务端时钟误差 < 60s
  • [ ] 重试逻辑会重新生成 timestamp / nonce / apiSignature

验证项 方法 结果

#2. 错误码

以 data.dataCode 为准。 错误描述在 data.dataMsg（中英文混合，不要用文案做判断）。

#2.1 线上错误码

dataCode 含义 典型触发 客户端/服务端处理
0 成功 — 正常渲染
1001 签名错误 签名串/密钥/nonce/URI 不一致；paramMd5 不匹配；pkgName 与登记不符；uid 不属于该 appId 检查 02；不要重试
1002 token 过期 / 无效 缓存超期、服务端重启、多实例覆盖 重新 getAccessToken 后重试一次
1003 时间戳过期 设备/服务器时钟漂移 > 5 分钟 校时后重新签名重试
3001 内容已下架 / 无播放地址 剧下架 / 地区不可用 / 该集无播放文件 从列表移除，回首页
9999 系统繁忙 服务端异常、下游超时 指数退避重试（最多 3 次），仍失败走降级文案

#2.2 仅参考实现（Demo mock）出现的错误码

Demo 的本地 mock 为了调试方便，额外返回下面几个码，线上不会出现。接入方写兜底时把它们归到对应线上码即可：

dataCode 含义 线上等价处理
4000 缺少幂等键 / 参数缺失（mock 内部校验） 修代码，按 1001 处理
4004 路由不存在（mock 内部） 修路径
5000 mock 内部异常 按 9999 重试

传输层：code=200 表示请求已被服务端处理（业务成败看 data.dataCode）；code=500 + 非 200 HTTP 状态码表示网关/服务端异常，按网络错误处理。

错误码全集与《LAAFFIC Content SDK 技术契约》一致；未列出的码一律按 9999 处理并上报给我们。

#3. 频率限制

接口 默认限制 说明
getAccessToken 单 uid 1 次/分钟 频繁调用视为异常，可能触发风控
只读接口（语种/分类/标签/列表/搜索/详情/热词/点赞/收藏） 单 uid 20 QPS 正常分页浏览远低于此
log/play 单 uid 30 次/分钟 每集最多 5 个节点，超了丢包
userAction 单 uid 10 次/分钟 连续点赞/取消会限流
refreshPlayUrl / refreshPlayFile 单 uid 30 次/分钟 一次最多刷新该剧全部集数，别整库刷

幂等：内容接口天然幂等（只读）；log/play 重复上报不报错；userAction 是状态型操作（status 显式指定时幂等）。

#4. 服务端接入配方（按这个顺序写，1 天能写完）

  1. HTTP 客户端：超时 5s、重试 2 次（仅网络错误/5xx）、把 timestamp/nonce/apiSignature 放在拦截器里（不要缓存签名）。
  2. Token 管理：按 uid 缓存 {token, expireAt}，提前 5 分钟刷新；1002 → 刷新一次并重试。
  3. 内容：getLanguageList → getCategoryList/getTagList（可缓存 1h）→ getDefaultDramasList(pageIndex, count, { languageCodes, categoryCode, sort })。
  4. 详情：getDefaultDramasList + vids:[vid]（count:1），不要另造详情接口。
  5. 播放：refreshPlayUrl(vid,[ep]) 或 refreshPlayFile(vid,[ep])，缓存到 expireTime - 60s；只用 playInfoUrl 或只用 fileId+playerSign，不要混用。
  6. 埋点：播放中 log/play 上报 PLAY_START/25/50/75/END（每节点一次）。
  7. 监控：按 dataCode 维度打点，1001/1002 突增要告警（通常是密钥或时钟问题）。

奖励、金币、任务、商店、广告、支付不在这套接口里：由客户自己的服务端实现，我们不参与、不结算、不存储。

接口字段以 internal/API_CANONICAL.md 与随包 Demo 参考实现为准。能力边界见 00 接入模式；SDK 侧接入见 04/05/06。

#2.4 生产形态：服务端换 token（推荐）

前端不持密钥，token 与签名都由你的 BFF 提供：

js
await LCDK.init({
  appId: 'laffic_demo_001',
  uid: 'demo_user_8848',
  pkgName: 'ai.laffic.demo',
  baseUrl: 'https://open.laaffic.io/sdk',
  // 1) 你的 BFF 返回短期 token（例如 10 分钟）
  tokenProvider: async () => {
    const res = await fetch('/api/laffic/token', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ uid: 'demo_user_8848' }),
    });
    const data = await res.json(); // { token, expiresIn }
    return data.token;
  },
  // 2) 签名也交给 BFF（前端拿不到 appSecret）
  signer: async ({ method, uri, timestamp, nonce, body }) => {
    const res = await fetch('/api/laffic/sign', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ method, uri, timestamp, nonce, body }),
    });
    return (await res.json()).apiSignature;
  },
});

signer 会带来一次额外网络往返。若你的接口已经由 BFF 代理（形态 C，见 02 §9），可以直接让 BFF 返回业务数据，前端只做渲染。

#4.4 播放进度上报 logPlayInfo

js
// 每集一条会话；25/50/75/100 各报一次
function bindPlayLog(video, ep) {
  const sessionId = `s_${Date.now()}_${Math.random().toString(36).slice(2, 10)}`;
  const fired = new Set();

  const report = (action, positionMs) => {
    LCDK.logPlayInfo(ep.fileId, action, Math.round(positionMs), { sessionId });
  };

  video.addEventListener('play', () => {
    if (!fired.has('PLAY_START')) { fired.add('PLAY_START'); report('PLAY_START', 0); }
  });
  video.addEventListener('timeupdate', () => {
    if (!video.duration) return;
    const p = video.currentTime / video.duration;
    [[0.25, 'PLAY_PROGRESS_25'], [0.5, 'PLAY_PROGRESS_50'], [0.75, 'PLAY_PROGRESS_75']]
      .forEach(([threshold, action]) => {
        if (p >= threshold && !fired.has(action)) {
          fired.add(action);
          report(action, video.currentTime * 1000);
        }
      });
  });
  const end = () => {
    if (!fired.has('PLAY_END')) {
      fired.add('PLAY_END');
      report('PLAY_END', video.currentTime * 1000);
    }
  };
  video.addEventListener('ended', end);
  video.addEventListener('pause', end);            // 退后台/锁屏
  window.addEventListener('pagehide', end);
}
action 时机
PLAY_START play 后 100ms
PLAY_PROGRESS_25 / 50 / 75 首次越过对应进度
PLAY_END ended / pause / pagehide

这是纯内容埋点：只用于播放统计与播放地址/内容侧分析，不与任何奖励、广告结算挂钩。

#6. 错误处理

所有异步 API 失败都会 reject 一个 ErrorInfo（不是原生 Error）：

js
{ code: 1002, message: 'token expired', detailCode: 401, method: 'requestDefaultDramasList' }
code 来源 含义 处理
0 — 成功 —
1001 服务端 签名错误 / 参数注册错误 检查 appId/appSecret/pkgName；不重试
1002 服务端 token 过期 SDK 已自动换 token 重试一次；仍失败 → 重新 init()
1003 服务端 时间戳过期 校时后重试
3001 服务端 内容已下架 移除该内容，回列表
9999 服务端 系统繁忙 指数退避重试 ≤3 次
-1 本地 未知错误 打日志上报
-2 本地 网络错误/超时 展示重试按钮
-3 本地 响应解析失败 打日志；多为网关返回 HTML
-4 本地 无数据（空列表） 空态，不弹错
-6 本地 未初始化 先 await LCDK.init()
-7 本地 参数非法（如 vid 为空） 修代码
-8 本地 appSecret 非 16 字节 修配置
-9 本地 token 缺失（BFF 模式未返回） 检查 tokenProvider
-11 本地 播放器 Licence 初始化失败 检查 vodLicenseUrl 与域名授权
js
try {
  await LCDK.requestDefaultDramasList(1, 10);
} catch (e) {
  if (e.code === -2) return showRetry();
  if (e.code === 1002) { await LCDK.init(cfg); return retryOnce(); }
  if (e.code === 3001) return removeFromList();
  showToast(`加载失败（${e.code}）`);
}

#8. 最佳实践（直接影响留存与性能）

建议 原因
列表用 count: 20 分页 列表每部剧只带第 1 集，响应小、首屏快
图片用 thumbnailMedium/Small 首屏只加载 240px 宽，节省 70% 流量
语种/分类/标签缓存 1h 这些数据几乎不变
播放地址按 expireTime - 60s 刷新 避免播放中断，也别每集都刷
预刷下一集 用户切集时秒开；一次最多 10 集
进度节点只报一次 每个节点只报一次，重复上报浪费且会被去重
页面隐藏时补 PLAY_END 否则观看时长统计偏低、播放会话不完整
销毁播放器 pagehide 时 hls.destroy() / player.dispose()，避免内存泄漏
不要缓存 token 到 localStorage 短期 token 会被拿走；内存缓存足够

#4.1 ExoPlayer（推荐，标准 HLS）

kotlin
class MyPlayerActivity : AppCompatActivity() {
    private var player: ExoPlayer? = null

    private fun start(vid: String, episode: Int) {
        ContentSDK.refreshPlayUrl(vid, intArrayOf(episode), object : ContentSDK.Callback<List<PlayInfo>> {
            override fun onSuccess(list: List<PlayInfo>) {
                val info = list.firstOrNull { it.index == episode } ?: return
                val exo = ExoPlayer.Builder(this@MyPlayerActivity).build().apply {
                    setMediaItem(MediaItem.fromUri(info.playInfoUrl))
                    prepare()
                    playWhenReady = true
                }
                player = exo

                // 进度上报：25/50/75/END
                val fired = mutableSetOf<String>()
                exo.addListener(object : Player.Listener {
                    override fun onPlaybackStateChanged(state: Int) {
                        if (state == Player.STATE_ENDED) {
                            if (fired.add("END")) ContentSDK.logPlayInfo(info.fileId, "PLAY_END", exo.currentPosition)
                        }
                    }
                })
                exo.addListener(object : Player.Listener {})

                // 每 500ms 检查一次进度节点（生产建议用 Handler 定时器，注意页面销毁时移除）
                val ticker = object : Runnable {
                    override fun run() {
                        val duration = exo.duration.takeIf { it > 0 } ?: return
                        val p = exo.currentPosition.toDouble() / duration
                        listOf(0.25 to "PLAY_PROGRESS_25", 0.5 to "PLAY_PROGRESS_50", 0.75 to "PLAY_PROGRESS_75")
                            .forEach { (threshold, action) ->
                                if (p >= threshold && fired.add(action)) {
                                    ContentSDK.logPlayInfo(info.fileId, action, exo.currentPosition)
                                }
                            }
                        exo.handler.postDelayed(this, 500)
                    }
                }
                ticker.run()

                // 播放行为上报
                ContentSDK.userAction("played", vid, episode)
            }

            override fun onFail(error: ContentSDK.ErrorInfo) {
                toast("播放地址获取失败 ${error.code}")
            }
        })
    }

    override fun onDestroy() {
        player?.release()
        player = null
        super.onDestroy()
    }
}

#7. 错误码

ContentSDK.ErrorInfo { code, message, detailCode, requestId }

code 来源 含义 处理
1001 服务端 签名/注册参数错误 检查 appId/appSecret/pkgName，不要重试
1002 服务端 token 过期 SDK 自动换 token 重试一次；仍失败 → 重新 init
1003 服务端 时间戳过期 校准设备时间（自动时间开启）
3001 服务端 内容已下架 移除内容，回列表
9999 服务端 系统繁忙 指数退避重试 ≤3 次
-1 本地 未知错误 上报
-2 本地 网络错误/超时 重试按钮
-3 本地 解析失败 打日志
-4 本地 无数据 空态
-6 本地 未初始化 检查 Application 是否调了 init
-7 本地 参数非法 修代码
-8 本地 appSecret 非 16 字节 修 BuildConfig
-11 本地 播放器 Licence 失败 检查 initVodLicense 与网络
-12 本地 播放器不可用（未引入/初始化失败） 检查依赖

#9. 注意事项（上线前逐条确认）

# 事项 正确做法 错误后果
1 初始化位置 Application.onCreate() 放 Activity → 冷启动竞态、init 失败
2 uid 稳定性 登录后 setUid(uid)，未登录用设备级临时 uid 换 uid = 换账号，收藏/已看全丢
3 pkgName 与后台登记逐字符一致 1001，init 永远失败
4 网络权限与明文 INTERNET + 仅白名单开 cleartext 弱网/内网调试莫名失败
5 播放器释放 onDestroy 里 release() / stopPlay() 内存泄漏、后台继续播放耗电
6 退后台 onPause 暂停 + 补 PLAY_END 观看时长统计偏低、播放会话不完整
7 进度节点 25/50/75/100 各上报一次（logPlayInfo） 重复上报浪费且会被去重
9 播放地址缓存 缓存到 expireTime - 60s 再刷新 过期地址黑屏/401
10 内容分级 按分级标签展示，18+ 内容对未成年不可见 过审风险（09）
11 密钥 BuildConfig + 服务端换 token appSecret 被反编译 = 全量盗用
12 覆盖安装 uid 存 SharedPreferences / 你自有账户体系 升级后收藏"归零"（其实是换 uid）

swift
import AVFoundation
import AVKit
import LAAFFICContentSDK

final class MyPlayerViewController: UIViewController {
    private var player: AVPlayer?
    private var timeObserver: Any?
    private var fired: Set<String> = []
    private var sessionId = "s_\(Int(Date().timeIntervalSince1970 * 1000))"

    func start(vid: String, episode: Int) {
        LAAFFICContentSDK.shared.refreshPlayUrl(vid: vid, episodes: [episode]) { [weak self] result in
            guard let self else { return }
            switch result {
            case .success(let list):
                guard let info = list.first(where: { $0.index == episode }) else { return }
                self.play(info: info, vid: vid, episode: episode)
            case .failure(let error):
                self.toast("播放地址失败 \(error.code)")
            }
        }
    }

    private func play(info: LAAFFICPlayInfo, vid: String, episode: Int) {
        let item = AVPlayerItem(url: info.playInfoUrl)
        let player = AVPlayer(playerItem: item)
        self.player = player
        player.isMuted = true
        player.play()

        // 播放行为上报
        LAAFFICContentSDK.shared.userAction(.played, vid: vid, episode: episode)
        LAAFFICContentSDK.shared.logPlayInfo(fileId: info.fileId, action: .playStart, positionMs: 0)

        // 进度节点：25 / 50 / 75 / END
        timeObserver = player.addPeriodicTimeObserver(
            forInterval: CMTime(seconds: 0.5, preferredTimescale: 600), queue: .main
        ) { [weak self] time in
            guard let self, let item = player.currentItem else { return }
            let duration = item.duration.seconds
            guard duration.isFinite, duration > 0 else { return }
            let progress = time.seconds / duration
            let marks: [(Double, LAAFFICPlayAction, String)] = [
                (0.25, .progress25, "PLAY_PROGRESS_25"),
                (0.50, .progress50, "PLAY_PROGRESS_50"),
                (0.75, .progress75, "PLAY_PROGRESS_75"),
            ]
            for (threshold, action, key) in marks where progress >= threshold && !self.fired.contains(key) {
                self.fired.insert(key)
                LAAFFICContentSDK.shared.logPlayInfo(fileId: info.fileId, action: action,
                                                     positionMs: Int64(time.seconds * 1000))
            }
            if progress >= 0.9 { self.reportProgress(info: info, vid: vid, episode: episode, progress: progress) }
            // 通知 observer 只处理一次 90% 心跳
        }

        NotificationCenter.default.addObserver(
            forName: .AVPlayerItemDidPlayToEndTime, object: item, queue: .main
        ) { [weak self] _ in
            guard let self, self.fired.insert("END").inserted else { return }
            LAAFFICContentSDK.shared.logPlayInfo(fileId: info.fileId, action: .playEnd,
                                                 positionMs: Int64(info.duration * 1000))
        }
    }

    deinit {
        if let observer = timeObserver, let player { player.removeTimeObserver(observer) }
        NotificationCenter.default.removeObserver(self)
    }
}

08 · 埋点与指标（内容侧）

你会得到什么：内容与播放事件的触发时机、必填字段、JSON 示例、上报批次与去重策略，以及 D1/D7/时长/完播率/内容渗透率的可复算公式。 能力范围：LAAFFIC 只提供内容与播放；奖励、任务、商店、广告、支付等埋点由客户自行定义，不在这份规范里。

事件名与字段以本篇定义为准。事件是给数据用的，不是给 UI 用的：客户端 UI 怎么变都不该改事件名，否则历史数据断档。

#1. 事件模型

层 事件 用途
SDK / 会话 sdk_init 初始化成功率、耗时、版本分布
内容曝光 content_list_view → content_detail_view 剧场/列表曝光 → 详情转化
播放漏斗 content_play_start → content_play_progress → content_play_end 起播、进度、完播、时长
播放行为 userAction（collect / like / played） 收藏、点赞、已看（走 /sdk/app/userAction 接口）

命名规范：域_动作，全小写 + 下划线；不要带版本号（版本放公共字段 sdkVersion）。

不包含：奖励、任务、商店、转盘、广告曝光/奖励。这些属于客户自己的 App 逻辑，需要的话由客户在自己的埋点体系里定义。

#2. 事件总表

事件 触发时机 关键字段 上报方 频次
sdk_init init() 成功（失败也建议上报，用 success=false） appId, uid, durationMs, version, success SDK 自动 1 次/会话

content_play_progress 25/50/75/100% 首次越过 vid, episode, percent SDK 自动（logPlayInfo） 每集 ≤4 次

#4. 上报通道（客户端 → 你的数据平台）

项 建议
通道 独立于业务接口的埋点端点（/track），避免被业务限流影响
批量 10 条或 5 秒一批，谁先到触发谁
失败 指数退避重试 3 次（200ms → 1s → 5s）；仍失败落本地队列
本地队列 最多 500 条，FIFO 丢弃最旧；App 重启后补发

离线 无网时只缓存关键事件（content_play_start / content_play_end），其余丢弃

#5. 指标口径（可直接照着算）

指标 公式 说明

详情转化率 content_detail_view / content_list_view 列表质量与封面/标题吸引力

#2. 签名类错误（1001 全家族）

现象 根因 验证 修复
一直 1001，换语言仍错 密钥错/长度错 用 02 §6 固定输入跑 Node/Python 对齐密钥或实现
Node 对 Java 错 Java 用了 NoPadding/自写填充 打印签名串前 40 字符比较 AES/CBC/PKCS5Padding
偶发 1001 body 被二次序列化（字段重排/美化/空格） 记录"签名用 body md5"与"发送 body md5" 先 JSON.stringify 再同时用于签名与发送
1001 且提示 nonce 重试没换 nonce 打印每次 nonce 重试必须重新生成 timestamp + nonce + 签名
Base64 解不开 URL-safe Base64 / 带换行 echo -n "$sig" \| base64 -d 标准表、单行、无空格
Java 端拿不到中文 body 编码不是 UTF-8 body.getBytes(StandardCharsets.UTF_8).length 统一 UTF-8

记住：签名是"方法+URI+时间戳+nonce+body"五行的 AES-CBC，不是对整个请求做 HMAC。 头里的 appId/token 不参与签名。

#11. 一键自检（脚本化，CI 可跑）

bash
#!/usr/bin/env bash
# laffic-smoke.sh —— 上线前 60 秒冒烟（需要 TOKEN 与 baseUrl）
set -euo pipefail
BASE_URL="${BASE_URL:-https://open.laaffic.io/sdk}"
TOKEN="${TOKEN:?需要 TOKEN}"
BODY='{"baseInfo":{"language":"zh","pkgName":"ai.laffic.demo"},"data":{}}'

for path in /sdk/app/getLanguageList /sdk/app/getCategoryList /sdk/app/getDefaultDramasList \
            /sdk/app/getPlaceholder; do
  code=$(TOKEN="$TOKEN" BASE_URL="$BASE_URL" \
    ./docs/tools/laffic-curl.sh --send "$path" "$BODY" \
    | python3 -c 'import json,sys; print(json.load(sys.stdin)["data"]["dataCode"])')
  echo "$path -> dataCode=$code"
  [ "$code" = "0" ] || { echo "FAIL $path"; exit 1; }
done
echo "smoke OK"
